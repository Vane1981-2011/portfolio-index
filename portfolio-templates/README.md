# 三份总监岗作品模板

> 内审方案 + 内控矩阵 · 13 周现金流 + 集团快报 · 土增税清算 + 税务风险看板
> 每份 **2 页 A4**，示例数据，可打印、可在线预览、可替换为真实项目数据后复用。

---

## 一、这是什么

三份用于审计总监 / 财务总监 / 税务总监岗位的作品模板。它们不描述“我做过什么”，而是把**方法、口径、勾稽关系**直接摊开：

| 模板 | 回答的问题 | 核心方法 |
|:--|:--|:--|
| 审计 `audit/` | 审计怎么做、做到什么程度 | 重要性四基准取孰低、风险矩阵、程序与抽样、COSO 五要素、缺陷三档与整改验证 |
| 财务 `finance/` | 现金能不能撑住、集团经营怎么样 | 13 周滚动预测、缺口与安全线、20 家合并桥、预算偏差与红黄绿灯 |
| 税务 `tax/` | 土增税要交多少、税务风险在哪 | 五项扣除、开发费用 A/B、分类计算与四级累进、20% 测试、12 项风险指标 |

所有金额、公司名、比例均为**合成示例**；页面显著标注“示例数据 / 脱敏模拟 / 非真实企业数据”。

## 三、构建与验证

```bash
cd portfolio-templates

# 1. 构建（HTML + PDF）
python3 scripts/build_templates.py

# 只生成 HTML，不导出 PDF
python3 scripts/build_templates.py --no-pdf

# 2. 验证：177 项，失败即 rc=1
python3 scripts/validate_templates.py

# 3. 排查分页：打印媒体下每页实际高度（可用 277mm）
python3 scripts/measure_pages.py

# 4. 导出简历落地页 PDF（A4 单页，链接改写为公开 HTTPS）
python3 scripts/export_landing_pdf.py \
  --out "$HOME/Desktop/保利发展 2026 半年报分析.pdf"
```

> Chrome 直接 `--print-to-pdf` 会把页面链接保存为 `file:///...` 本地路径，换机即失效；
> `export_landing_pdf.py` 在导出后把 5 个链接统一改写为
> `https://vane1981-2011.github.io/portfolio-index/portfolio-templates/...`。

依赖：Python 3.10+、Jinja2、pypdf；PDF 导出使用本机 Chrome/Chromium/Edge（headless）。
测量脚本额外依赖 Playwright（`channel="chrome"` 复用本机 Chrome）。

## 三·五、公开数据案例（保利发展 600048）

`case-baoli/` 用 2026 年半年报的公开数据跑一遍三套方法，数据源为东方财富 / akshare，采集日 2026-10-22，单位亿元。

| 视角 | 用了哪些公开数据 | 明确不做什么 |
|:--|:--|:--|
| 审计 | 利润总额、营业收入、资产总额、净资产 → 重要性；应收、存货、合同负债、少数股东、有息负债、有效税率 → 风险矩阵 | 不评价内控运行有效性，不出审计意见 |
| 财务 | 合并利润表、资产负债表、现金流量表、按地区主营构成（17 个区域）→ 区域快报、四年同期趋势、现金流质量 | 不做项目级回款、监管资金、13 周内部预测 |
| 税务 | 税金及附加、本期土增税 10.51 亿、应交土增税 87.16 亿、所得税费用与调整表、递延所得税、合同负债、少数股东损益 | 不算项目级土增税清算，不判断预缴是否充分 |

关键数字（可复核）：营业收入 1,028.60 亿元（同比 −11.98%）、归母净利 19.59 亿元（−40.84%）、毛利率 13.03%（上年同期重述口径 15.29%）、经营现金流 245.52 亿元（+53.28%）、有效税率 42.56%、本期土增税 10.51 亿元、应交土增税 87.16 亿元、存货 6,305.09 亿元。有效税率偏高的主因是附注中“本期未确认递延所得税资产”+9.98 亿元。

重新取数：更新 `data/case_baoli.json` 的 `income` / `balance` / `cashflow` / `segments` / `trend`，重跑构建与校验。**不要**把公开数据案例的结论写成“审计发现”或“税务意见”。

## 四、数据字段与派生关系

**原则：JSON 只放原始输入，所有派生值由 `build_templates.py` 计算。** 不要手填 OM、缺口、合并数、税额——否则模板与校验会同时失去意义。

### 4.1 审计 `audit_sample.json` → `audit/index.html`

| 输入 | 派生值 | 公式 |
|:--|:--|:--|
| `benchmarks[].amount × rate` | `om` | 四个基准结果取最小值 |
| `om` | `pm` | `om × 60%` |
| `om` | `trivial` | `om × 5%` |
| `risks[]` | `risk_count` / `fraud_count` | 行数 / `fraud=true` 的行数 |
| `controls[]` | `control_count` / `kcp_count` / `untested_count` | 行数 / `kcp=="是"` / `result=="未测试"` |
| `deficiencies[]` | `def_counts` / `closed_count` / `rect_rate` | 三档计数 / 已验证关闭 / 关闭÷总数 |

页面上“风险矩阵”的舞弊行用**首列红色竖线**标记（避免把胶囊挤成两行）；表注已说明图例。

### 4.2 财务 `cashflow_sample.json` + `group_sample.json`

13 周（`finance`）：

```
当周期末 = 上周期末 + 流入 − 流出
缺口     = MAX(0, 最低保有 − 当周期末)
累计缺口 = Σ 缺口
安全线覆盖率 = 第 13 周末现金 ÷ 最低保有
```

集团（`group`）：

```
合并收入 = Σ主体收入 − 内部交易抵消
合并成本 = Σ主体成本 − 内部成本抵消
合并净利 = Σ主体净利 − 内部利润抵消
归母净利 = 合并净利 − 少数股东损益
红灯：完成率 <85% 或净利为负
黄灯：完成率 <95% 或经营现金流为负
绿灯：其余
```

**跨页勾稽**：`group_sample.json` 的 `cash` 必须等于 13 周末现金；构建脚本会先断言，不一致直接 `rc=2` 退出。

### 4.3 税务 `land_vat_sample.json` → `tax/index.html`

```
收入        = Σ 面积 × 单价 ÷ 10000
开发费用 A  = 利息 + (土地 + 开发成本) × 5%     # 能提供金融机构证明时强制适用
开发费用 B  = (土地 + 开发成本) × 10%           # 不能提供证明时才适用
加计 20%    = (土地 + 开发成本) × 20%
扣除        = 土地 + 开发成本 + 开发费用 + 税金 + 加计 20%
增值额      = 收入 − 扣除
增值率      = 增值额 ÷ 扣除
税额        = 增值额 × 税率 − 扣除 × 速算扣除系数
```

| 增值率 | 税率 | 速算扣除系数 |
|:--|--:|--:|
| ≤50% | 30% | 0 |
| 50%–100% | 40% | 5% |
| 100%–200% | 50% | 15% |
| >200% | 60% | 35% |

**分类计算**：普通住宅单独核算，其他业态合并核算。**成本按可售面积均摊，但只扣除已售部分**：普通住宅 78,000㎡ 全部售出，其他业态已售 43,000㎡ / 可售 50,600㎡，未售车位 7,600㎡ 对应扣除 6,900.8 万元暂不扣除（待尾盘销售按尾盘规则处理）。普通住宅增值率 ≤20% 时免征，否则按全部增值额计税。页面没有把“整体一个税率”的简化结果当作申报数。

`tax_risk_sample.json` 的评分：

```
加权得分 = Σ(权重 × 分值) ÷ Σ权重 ÷ 2 × 100     # 绿/黄/红 = 0/1/2
风险等级 = 得分 ≥70 高；≥40 中高；≥20 中；其余 低
```

看板中的“土增预缴/清算差异”和“影响金额”需与第 1 页复算值一致，`validate_templates.py` 会交叉检查。

## 五、177 项校验覆盖什么

`scripts/validate_templates.py` 分四组：

1. **版式**：每份 PDF 恰好 2 页、A4 尺寸（209.9×297.0mm）、HTML 无 `{{ }}` / `Undefined` / `AUTO` 占位。
2. **数值**：审计 14 项、财务 25 项（13 周 15 + 集团 10）、税务 31 项、公开数据案例 21 项，含分类复算、情景方向与跨页一致性。
3. **声明**：每份含两处以上“示例数据”与“非真实”边界；审计明示“非执业审计 / 未持 CPA / CIA”；税务明示“不构成税务意见”且 2026 年第 3 号公告标注“核对原文”；禁用“我曾为…”“持有 CPA”等虚假表述。
4. **打印**：`@page A4 portrait`、`thead` 跨页重复、行与卡片不跨页、颜色强制打印、打印态覆盖窄屏媒体查询、窄屏单列。

校验有判别力：任一数值改动（例如把 `prepaid` 改成 6,000）都会让对应项转红。

## 六、替换为真实数据

1. **改数据**：只改 `data/*.json` 的原始输入。名称保留“项目公司 A–T”这类代号，不要在模板里写真实客户名。
2. **重算**：`python3 scripts/build_templates.py`。派生值自动进 `data/derived.json`。
3. **验证**：`python3 scripts/validate_templates.py`，必须 177/177。
4. **导出**：Chrome headless 已自动生成 PDF；如需重新导出，删除旧 PDF 后重跑。
5. **打印**：A4 纵向、边距 10mm×11mm；页面按 2 页设计，**不要**在打印对话框里勾选“缩放以适应”。

注意事项：

- 金额单位在数据里是**万元**；改单位要同时改页面文案（`unit`）。
- 审计重要性基准比例是常见区间，不是准则强制值；替换时保留“为什么选这个比例”的说明。
- 税金的计算依赖当地附加税税率与印花税口径；示例按 9% 增值税、12% 附加、0.05% 印花税估算，真实项目需逐项核对。
- 土增税普通住宅标准由省级政府规定，`land_vat_sample.json` 里的 20% 测试只在“已按当地标准认定为普通住宅”时成立。

## 七、诚实边界

- **示例数据**：所有金额、比例、公司名均为合成，不得写成个人业绩或真实项目结论。
- **资质边界**：审计模板为方法论演示，作者未持 CPA / CIA，不构成审计意见或鉴证结论。
- **税务边界**：税务模板不构成税务意见；政策文号、施行日期、地方口径须在引用前核对原文。
- **阈值边界**：税务风险阈值来自稽查实务经验，不是官方公布值；关联交易 10% 是复核阈值，不是税法安全港。
- **方法边界**：模板展示的是“怎么算、怎么勾稽、怎么留痕”，不替代现场证据、职业判断与主管机关口径。
- **工具边界**：校验脚本只做机械核对，`UNDECIDABLE` 不等于 `FAIL`；脚本通过不等于结论正确。

## 八、文件指纹

构建后可用以下命令复核 PDF 是否被替换：

```bash
shasum -a 256 audit/audit.pdf finance/finance.pdf tax/tax.pdf
```

（指纹随每次构建变化，不在此处硬编码，避免“文档里的哈希”与产物漂移。）
